# Windows 邮件目录迁移保护

## 要解决的问题

「迁移当前邮件到此目录」会把源账号目录逐个复制到目标路径。原实现会覆盖目标里的同名文件，并删除目标 SQLite 的 WAL 和 SHM 文件。复制或切换失败时，客户端可以切回原目录，目标已有数据却可能已经被改写。

## 迁移规则

- 如果待迁移账号在目标中已有同名目录、文件或链接，终止整次迁移并提示用户改用「直接使用已有邮件数据（复用）」或选择其他目录。目标中与此次迁移无关的账号和文件可以保留。
- 先将全部待迁移账号复制到目标卷上的独立暂存目录。复制完成后，再将新账号目录移入最终位置。Windows 使用拒绝替换目标的目录移动操作。新缓存连接打开后，才保存新的存储路径配置。
- 复制、发布目录或切换失败时，保留原存储配置与源邮件库，尽量清理本次创建的暂存文件和已发布的新目录。配置切换失败或打开新目录失败需要反馈给调用方。
- 「复用」继续挂载已有邮件库。此次修复限于邮件目录迁移。

迁移期间如果进程被强制结束，目标可能留下暂存目录或本次刚创建的账号目录。原有账号目录从预检查到发布都受覆盖保护。

## 验收

1. 目标无冲突时，迁移后的邮件库可正常读取，源目录仍可使用。
2. 目标已有同名账号目录时，整次迁移失败。比对原有邮件库、WAL、SHM 和附件内容，并检查其他待迁移账号目录未被发布。
3. 复制遇到文件占用而失败，或复制完成后配置保存失败时，仍从原目录读取邮件。目标已有数据原样保留，重试可以继续。
4. 复用已有目录成功，原有缓存可读。运行 Windows x64 工作区测试、格式检查和 diff 检查。
